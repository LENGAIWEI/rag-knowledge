#9. MySQL 知识库
## 1. MySQL 基础
关系型数据库，InnoDB 引擎（默认，支持事务、行锁）；MyISAM 不支持事务，表锁，已经很少使用。
## 2. InnoDB 核心
- 事务 ACID：原子性、一致性、隔离性、持久性
- 事务隔离级别：
1. READ UNCOMMITTED 读未提交
2. READ COMMITTED 读已提交（Oracle 默认）
3. REPEATABLE READ 可重复读（MySQL InnoDB 默认，MVCC 实现，解决幻读）
4. SERIALIZABLE 串行化，最高级别，性能最差
## 3. MVCC 多版本并发控制
InnoDB 实现隔离级别核心，不加锁实现读写并发。
核心：undo log 版本链 + read view，查询读取历史快照版本，读写不阻塞。
解决：脏读、不可重复读；RR 级别下通过 MVCC + 间隙锁解决幻读。
## 4. 锁机制
- 行锁：InnoDB，锁定单行；前提命中索引，否则退化为表锁
- 表锁：锁定整张表，MyISAM，InnoDB 也可以手动加
- 意向锁：表级意向共享 / 排他锁，辅助判断行锁冲突
- 间隙锁、临键锁：RR 隔离级别，防止幻读
## 5. 索引（高频重点）
InnoDB 索引底层：B + 树
特点：叶子节点有序链表，全部数据在叶子，非叶子只存索引键，适合范围查询。
分类：
1. 主键索引（聚簇索引）：叶子存放完整行数据；一张表只能一个聚簇索引。
2. 二级索引（非聚簇）：叶子存放主键值；回表查询，拿到主键再查聚簇索引获取完整数据。
3. 联合索引：多个字段组成索引，**最左前缀原则**。
4. 覆盖索引：查询字段全部在索引内，不需要回表，性能极高。
### 索引失效常见场景
1. 违背最左前缀
2. 索引字段做函数运算、隐式类型转换
3. like '% xxx' 前缀模糊匹配
4. or 连接，一侧无索引
5. mysql 优化器判断全表扫描更快，放弃索引
## 6. 日志文件
- redo log：重做日志，崩溃恢复，保证持久性，先写日志再刷盘 WAL
- undo log：回滚日志，MVCC 版本链，事务回滚
- binlog：二进制日志，主从复制、数据恢复，记录 SQL 事件
## 7. SQL 优化思路
1. 加合适索引，避免索引失效
2. 避免 select *，使用覆盖索引
3. 减少 join，join 字段建立索引
4. limit 大分页优化（id 分页）
5. 避免大事务，长事务占用 undo，影响性能
## 8. 慢 SQL 排查
开启 slow_query_log，记录超过 long_query_time 的 SQL；explain 查看执行计划，看 type、key、rows、Extra。
explain type 性能排序：system>const>eq_ref>ref>range>index>ALL
## 9. 面试问答
Q：聚簇索引和非聚簇索引区别？
A：聚簇索引叶子节点存储完整行数据；二级索引叶子存储主键，需要回表查询。
Q：MVCC 是什么？
A：多版本并发控制，通过 undo log 生成数据快照，实现读写不阻塞。
Q：B + 树相比 B 树优势？
A：B + 树叶子链表，范围查询方便；非叶子节点不存数据，一页可以存放更多索引，IO 次数更少。
